# 43 — Golden Case Production Runbook

## Purpose

The first Black Hawk Down case is both product content and a regression fixture. It must be curated with more discipline than a demo article.

## Step 1 — Define the case

- film title, year, territory, and exact cut;
- user curiosity: “Why did everything go wrong?”;
- normalized objective;
- boundaries: film production, historical operation, politics, and aftermath included or excluded;
- spoiler policy;
- primary investigation mode;
- first theory branch.

Use `templates/movie-case-brief.md`.

## Step 2 — Build source inventory

Target 20–40 sources across:

- film itself through permitted observations and exact version identity;
- screenplay or production material where lawful;
- Mark Bowden's reporting with edition-aware locations;
- official or archival records;
- participant oral histories and interviews;
- independent historical scholarship;
- maps and timelines;
- contemporaneous journalism;
- production interviews and criticism;
- community leads only where worth testing.

Each source receives identity, rights/access state, independence group, and resolver status.

## Step 3 — Create claim graph

Create explicit claims such as:

- expected mission duration;
- intelligence assumptions;
- command constraints;
- urban terrain effects;
- helicopter vulnerability;
- communications breakdown;
- convoy navigation;
- reinforcement and political constraints;
- casualty and aftermath accounts;
- film adaptation choices.

For every claim record:

- supporting evidence;
- counterevidence;
- uncertainty;
- source dependence;
- what the film depicts;
- what the historical evidence establishes;
- what remains interpretation.

## Step 4 — Verify locators manually

Open every locator used in a rendered beat. Record manual reviewer and result. Reject page numbers from unidentified editions and timecodes from unidentified video or film versions.

Use `templates/source-audit.md`.

## Step 5 — Author the canonical trail

Produce 8–12 major beats with:

- one unresolved opening;
- minimum context required;
- evidence arriving before conclusion;
- at least one genuine contradiction;
- at least one map/spatial causal moment;
- at least one user-inference pause;
- at least one branch opportunity;
- a local resolution that preserves open questions.

The fixture prose may be manually authored. The point is to establish the quality target the live system must eventually match.

## Step 6 — Build one theory branch

Example:

> The mission was structurally doomed before the first helicopter was hit.

The branch must contain:

- preserved user wording;
- normalized proposition;
- support lane;
- pressure lane;
- alternatives;
- unknowns;
- calibrated status;
- return to main trail.

## Step 7 — Produce notes and connection fixtures

Include:

- one user question;
- one counterpoint;
- one connection to a prior beat;
- one proposed cross-case connection marked unaccepted;
- one dismissed weak connection.

## Step 8 — Freeze expected outputs

Store:

- source IDs and fingerprints;
- locators;
- claim graph;
- beat sequence;
- branch assessment;
- expected trust states;
- expected UI events;
- cost-free deterministic mock output.

Any change becomes a versioned golden-case update with an eval report.

## Step 9 — Human review

Review with at least:

- one user unfamiliar with the history;
- one user familiar with the film;
- one domain-informed reviewer;
- one documentary or video-essay creator.

The case is ready only when it is understandable, inspectable, paced, and still leaves the user doing intellectual work.
