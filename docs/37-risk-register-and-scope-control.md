# 37 — Risk Register and Scope Control

## Product risks

| Risk | Early signal | Mitigation | Kill/decision gate |
|---|---|---|---|
| Beautiful one-time demo | praise without second case | test voluntary continuation | no repeat cohort after iterations |
| Chatbot drift | console accumulates answers | route work into main branch | reject features that require transcript UI |
| Answer collapse | users skim to conclusions | preserve pauses and evidence | human eval flags passive consumption |
| Creator wants only scripts | users skip investigation | separate closure mode | decide whether that is a different product |
| Too many modes | onboarding confusion | infer temporary mode | keep only validated modes |

## Research risks

| Risk | Mitigation |
|---|---|
| fabricated locators | resolver validation and open-original tests |
| repeated claims appear corroborated | independence groups and origin tracing |
| inaccessible books/films | link-only state, edition-aware locators, user-owned inputs |
| film-version mismatch | resolve exact cut before timecodes |
| creator intent overclaimed | treat statements as evidence, not final authority |
| community theory presented as fact | separate interpretation evidence lanes |

## Engineering risks

| Risk | Mitigation |
|---|---|
| monolithic “agent” route | stage-specific interfaces and jobs |
| streaming reorders case | stable sequence keys and insertion contracts |
| runaway cost | budgets, model routing, caching, curated V1 |
| model vendor coupling | typed provider interfaces and fixtures |
| extension expands attack surface | defer and isolate companion architecture |
| long case performance | progressive loading and anchor-safe virtualization |

## Founder risks

- building during finals without scope limits;
- polishing home page while core reading fails;
- mistaking personal obsession for market proof;
- adding every plausible specialist;
- designing autonomous work before foreground trust;
- treating a 10/10 document as progress equivalent to a working case.

## Finals-safe build boundary

During finals, acceptable work is limited to:

- design tokens and motion prototype;
- curated Black Hawk Down fixture;
- typed contracts and schemas;
- deterministic UI vertical slice;
- one route at a time;
- short build sessions with a written stopping point.

Do not begin open-ended ingestion, extension compatibility, or autonomous missions during finals.

## Scope change protocol

Every new feature proposal must answer:

1. Which validated user behavior does it support?
2. Does it strengthen the Movie Investigator?
3. Can it be mocked before backend work?
4. What existing milestone does it delay?
5. What is removed if this is added?

Record accepted decisions in `decisions/` using the ADR template.
